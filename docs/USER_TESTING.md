# Click-through testing

This is the checklist for a pass that uses Sortlens the way a photographer does: launch the
window, click the control, and look at the result. A story is finished only when that interaction
passes. A failing story is fixed in the same pass and tried again. It is not skipped, and it is
not checked off from a unit test or a screenshot harness alone.

`docs/FEATURES.md` is the inventory. `docs/UX.md` is the layout the window is held to. This file
is the order a person walks them.

## How a pass runs

One wake walks several stories. A click that passes is short, so the wake keeps going. Feature
stories come first, in the order written. Interface stories start only after every feature story
is checked or recorded as blocked. The next wake starts again at the first story that is still
unchecked.

1. `git fetch` before editing so this file is the latest one on `main`. Other agents work in
   this repository. This pass does not take the plan loop's lease and does not ship a roadmap slice.
2. Launch the desktop app if it is not already showing a window: `cargo run -p sortlens`.
   Use a real library with photographs in it. If the machine has none, add one small folder of
   the owner's photos and say which folder. Do not invent a second app, and do not drive this
   through a browser. The window is a native egui app.
3. Take the next unchecked story. Do the clicks and keystrokes. Look at the window after each
   one. A pass needs the control to be reachable, the result to be the one the story names, and
   the screen to still match `docs/UX.md` (nothing clipped, overlapping, or left in English by
   accident).
4. When it passes, change `- [ ]` to `- [x]` and append one line to the log: the date, the
   story id, and what the window showed. Then take the next story in the same wake.
5. A story whose feature `docs/ROADMAP.md` lists as backlog, or as waiting on something outside
   the repository, is not built in this pass. Write `blocked: <reason>` in its note, leave the
   box unchecked, and continue with the next story.
6. If a story fails, errors, or needs a code change, stop the walk. Fix the smallest change
   that makes that story pass, and try it again in the window. When the gates that change
   requires are green (`cargo xtask ci`, and `cargo xtask screenshots` when `crates/ui`
   changed), commit the fix and the checklist on the current branch, push, and end the wake.
   Do not start another story after a fix.
7. If the wake only checked stories and changed no code, commit the checklist and push that
   too, so the next wake does not repeat them, then end. A blocked story is not a fix.

Destructive stories (delete, empty the rejects bin, apply a cull) use a copy of a folder, never
the only copy of a photograph.

## Field notes

Hard-won points from a pass, so the next one does not relearn them:

- Launch with `. ./scripts/env.sh` then `cargo run -p sortlens`. If cargo is blocked on a stale target lock, run `./target/debug/sortlens` directly instead of waiting.
- Take a screenshot with Cmd+Shift+3 and read the newest `~/Desktop/Screenshot*.png`. The image is 1920×1080 and the window is 1280×800 at about (320,69), so pixels map 1:1 to clicks. The chat preview is scaled: crop the PNG (PIL or `sips`) and measure a row before clicking. A y guessed from the preview can be 20–40 points out.
- At the default sidebar height the six sources are near y=354, 386, 415, 445, 474 and 503, and Pictures is near 570. They move when the panel scrolls or the window resizes, so crop before every click.
- The folder menu's `Add to favourites` is the pin; the row then carries a `★` prefix, and there is no separate Favourites section. `Colour` opens its swatches on hover, not on click; clicking the row can dismiss the menu and select the folder beneath it. The notice combines the two (`Pinned and yellow`).
- Source counts are scoped to the selected root: `All Photos` is the count inside the current folder, not the library total. The canvas title stays `Library`; the folder's name is in the breadcrumb (`Pictures › Sortlens Demo`). `Clear filters` also forgets the folder scope.
- The search field takes focus on launch, so `0–5`, `P`/`U`/`X` and `⌘K` type into it until the grid has focus. Click a photo first; the palette did not open while the field was focused.
- A menu is only clickable while it is open. Take a screenshot after each state change, and do not click a row underneath a just-closed menu.
- Folder search and folder sort (A07, A08) are not built: the FOLDERS header has no search or sort control. Record them blocked as roadmap work; do not build them during a pass. The same goes for a story blocked on a device, Xcode, or an Apple identity.
- A folder's `Remove from library`, a collection's delete row and a keyword's `Delete everywhere` each asked in the shared confirmation dialog as of UT-B17 (2026-11-27). Before that they acted on the click; if a menu row vanishes without a question, check that the dialog was not dismissed.
- A folder menu's rows are about 28 points apart and the last row sits near pointer y + 104. A click on its top edge can miss the row and shut the menu without doing anything, so screenshot the open menu and aim at the row's centre.
- After `Point at…` the canvas follows the repointed root. Before the fix it stayed on the old path, so the grid went empty until the folder row was clicked again.
- Screenshots stay on the Desktop and are never committed. The checklist and any fix are what go to git.
- Synthetic input, corrected on 2026-11-28: clicks land only through the legacy `CGPostMouseEvent` (a tiny ctypes helper against ApplicationServices); `CGEventPost` mouse taps and every CoreGraphics key event were dropped by this window. Text and single keys arrive with `System Events` `keystroke` or `key code`, but a chord needs its modifier held as its own event — `key down command`, then `key code 0`, then `key up command` — because egui takes the frame's `input.modifiers` from the modifier-change event, not from the key press, so a bare `keystroke "a" using command down` reads as an unmodified `A`. The keys that produced nothing after a canvas click were the app's fault, not the injector's: a cull session left open in the engine swallowed every press (UT-B15). Do not record a keyboard criterion as unverifiable before the app's own behaviour has been checked.
- Secondary clicks do arrive through `CGEventPost` (`kCGEventRightMouseDown`/`Up`, 2026-11-27): a photo's menu opened at the pointer with `Export…`, `Show in folder`, `Open in default app` and `Add to Collection`. The legacy helper's right mode acts as a left click, and a click on the scroll gutter beside the grid jumps the grid instead; earlier failures were a right-click on a Sources row and then on a grid the Rejects filter had emptied.
